# 0013. Проект серии `.zisc`: состояние и метаданные кадров в одном файле, без .json у снимков

Заменяет часть решения 0009 про `series.zscope-series.json`.

## Контекст

У каждого снимка серии лежал свой .json с метаданными. Пользователю это не понравилось: папка серии захламлена. Состояние серии хранилось в `series.zscope-series.json`, и серию открывали выбором папки. Серии в старом формате снимали только для проверки, рабочих серий в нём нет.

## Решение

В папке серии лежит файл проекта `<имя серии>.zisc` в формате JSON, `"format": "zi-scope-series/2"`. В нём:
- план;
- текущий шаг;
- статусы шагов;
- один список `Frames` с метаданными каждого файла снятых шагов. У каждой записи есть `File` — имя файла.

Снимки серии пишутся без .json, всегда: выключатель метаданных относится только к обычным снимкам. Серию открывают выбором `.zisc` («Открыть проект серии…»). Сохраняется она в тот файл, из которого её открыли. Формат `/1` не читается.

## Почему

- Отвергнуто: оставить .json у кадров и добавить проект рядом. Хлам в папке остаётся, а пользователь просил именно убрать его.
- Отвергнуто: подчинить список метаданных выключателю метаданных обычных снимков. Пользователь сказал, что выключатель — для обычных снимков, а метаданные серии нужны «в .zisc одним списком».
- Отвергнуто: читать старый `series.zscope-series.json`. Рабочих серий в этом формате нет, а миграция — лишний код.
- Отвергнуто: ассоциация `.zisc` в реестре для двойного клика. Пользователь сказал: «пока без реестров».
- Метаданные кадра — один тип `FrameMetadata` для серии и для обычного .json. Если описать два разных типа, их состав со временем разойдётся.

## Последствия

- Записи `Frames` сопоставляются с файлами по имени, а не по позиции. Если правка проекта вручную ломает имена, запись теряется, но под чужое имя не переезжает.
- Снимок, удалённый из ленты или в проводнике, проект увидит только при следующем открытии: шаг тогда станет «не снят».
- Если в папке несколько `.zisc`, предложение продолжить серию при запуске берёт самый свежий. Новая серия в папке с проектом после подтверждения удаляет прежние `.zisc`.
- Двойной клик по `.zisc` в проводнике программу не открывает.
