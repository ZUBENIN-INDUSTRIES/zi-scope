# 0012. Профили цвета в настройках, профили конфигурации — файлами .zscope; оба формата помечены версией

## Контекст

Нужны профили цвета и профили всей конфигурации с экспортом и импортом. Старые пресеты цвета уже лежат в `settings.json`.

## Решение

Профили цвета хранятся в `AppSettings.ColorProfiles`. Старые `Presets` один раз переносятся туда, после чего список пресетов очищается. Профили конфигурации хранятся отдельными файлами `%AppData%\ZI-scope\profiles\<имя>.zscope`. Внутри — полный `AppSettings` в JSON без списка самих профилей конфигурации. Экспорт и импорт используют тот же формат. Оба формата — JSON с полем `format` (`zi-scope-color/1`, `zi-scope-config/1`). Если формат не тот, файл отвергается с сообщением «Файл не является профилем ZI-scope», и ничего не меняется. Неизвестные поля из файлов более новой версии игнорируются.

## Почему

- Отвергнуто: хранить профили конфигурации внутри `settings.json`. Каждый профиль — полная копия настроек, поэтому файл рос бы рекурсивно, а сбой записи одного файла потерял бы и рабочие настройки, и все профили сразу.
- Отвергнуто: хранить профили цвета отдельными файлами. Они маленькие, их применяют часто, и они входят в конфигурацию (их переносит `.zscope`). Для обмена есть экспорт в `.zcolor`.
- Отвергнуто: формат без маркера версии. Тогда любой JSON — например, сам `settings.json` или файл серии — читался бы как профиль и молча портил бы настройки. Будущую смену формата тоже было бы не распознать.

## Последствия

- Файлы `.zcolor` и `.zscope` попадают к людям. Формат нужно развивать только совместимо: новые поля добавлять, старые не менять по смыслу, а при несовместимой смене поднимать номер версии.
- `.zscope` содержит всё, включая пути к папкам этого компьютера. На другом компьютере загруженная конфигурация может указывать на несуществующую папку снимков.
- Перенос пресетов односторонний: старая версия программы после него пресетов не увидит.
