# 0008. Распознавание подписи калибровки через Windows.Media.Ocr со сменой TargetFramework

## Контекст

Для калибровки по снимку нужно прочитать число с единицами над масштабной линией. Программа работает без интернета, а новые NuGet-пакеты без согласия пользователя не добавляются.

## Решение

Текст распознаёт встроенный в Windows 10/11 `Windows.Media.Ocr`, офлайн, на установленном английском или русском языке. Чтобы он был доступен, `TargetFramework` приложения и тестов меняется с `net8.0-windows` на `net8.0-windows10.0.19041.0`. Саму линию находит свой код (`Calibration/ScaleLineDetector`, без UI и библиотек). Если распознать не удалось, поле остаётся пустым, и его заполняют вручную в окне проверки.

## Почему

- Отвергнуто: Tesseract или другой OCR из NuGet. Это новый пакет, нативные библиотеки и файлы языковых моделей в папке переноса, и всё это без согласия пользователя.
- Отвергнуто: облачное распознавание. Программа не ходит в сеть.
- Отвергнуто: только ручной ввод числа. Он работает и остаётся запасным путём, но пользователь просил, чтобы программа сама распознала подпись.
- Отвергнуто: распознавать и линию через OCR или CV-библиотеку. Сплошной цветной отрезок надёжно находится простым поиском горизонтального прогона, и такой код тестируется на синтетических картинках.

## Последствия

- Минимальная ОС — Windows 10 версии 2004 (19041). На более старых системах программа не запустится.
- Качество распознавания зависит от языков OCR, установленных в Windows. Если нет ни английского, ни русского, число придётся вводить руками.
- Тестовый проект тоже привязан к Windows SDK-версии фреймворка, а вывод сборки лежит в папке `net8.0-windows10.0.19041.0`, а не в `net8.0-windows`.
- Вернуть прежний `TargetFramework` можно только вместе с отказом от распознавания.
