# 0002. Интерфейс: WPF + WPF-UI + свои эффекты в духе reactbits

## Контекст

Бриф просит «современный UI» и «готовые компоненты, внешне похожие на reactbits.dev». reactbits — библиотека React-компонентов для браузера. Программа уже написана на WPF (.NET 8), и через неё идёт живое видео с камеры.

## Решение

Окно остаётся на WPF. Базовые Fluent-контролы (FluentWindow, CardExpander, NumberBox, ToggleSwitch, Snackbar, ContentDialog) берутся из NuGet-пакета `WPF-UI`. Эффекты reactbits (Aurora, SpotlightCard, ShinyText, CountUp, ClickSpark, GlowButton) портированы как собственные контролы в `UI/Effects` и сделаны только на WPF-анимациях. Mica не используется. Этот вариант выбрал пользователь («WPF + стиль reactbits»).

## Почему

- Отвергнуто: WebView2 + React с настоящими компонентами reactbits. Кадры 1920×1440 при ~25 к/с пришлось бы передавать из нативного кода в браузерный движок, а это медленнее. Поставка перестала бы быть одним exe: понадобились бы рантайм WebView2 и сборка фронтенда, то есть лишняя зависимость на машине у микроскопа без интернета.
- Отвергнуто: только WPF-UI без своих эффектов. Он не даёт вида reactbits: в нём нет Aurora, свечения за курсором и искр.
- Отвергнуто: сторонние пиксельные шейдеры для эффектов. Это лишняя зависимость и риск на слабых видеокартах, а блюр, градиенты и анимации WPF дают тот же вид.
- Отвергнуто на ревью таска 02: Mica. Непрозрачный фон палитры reactbits (`#0B0B12` + Aurora) всё равно её перекрывает.

## Последствия

- Эффекты пишутся и поддерживаются своими силами. Новые компоненты reactbits не придут обновлением пакета: каждый нужно портировать вручную.
- `BlurEffect 120` на весь фон и постоянные анимации тратят GPU и CPU, которые нужны и обработке видео.
- Программа работает только под Windows.
- Обновления WPF-UI могут ломать стили, поэтому версию пакета придётся обновлять осознанно.
