# 0003. Цветокоррекция программная, экспозиция и усиление аппаратные

## Контекст

API камеры содержит аппаратные свойства BRIGHTNESS, CONTRAST, HUE, SATURATION, GAMMA, EXPOSURE и GAIN. Сохранённый файл должен выглядеть так же, как превью (R10.3), а всё должно работать и в демо-режиме без камеры.

## Решение

Экспозиция и усиление меняются в камере. Яркость, контраст, гамма, насыщенность, баланс белого, Ч/Б и негатив считаются в программе за один проход: 3 LUT на канал плюс насыщенность через яркость Rec.709. Одна функция `ImageProcessor.Apply` обрабатывает и превью, и кадр для файла (в полном разрешении).

## Почему

- Отвергнуто: аппаратная коррекция всех параметров. Набор свойств и их диапазоны отличаются между версиями камеры, сигнатуры API не проверены (ADR 0001), а у симулятора таких свойств нет. Пришлось бы делать отдельный путь для каждого источника кадров, и результат на экране и в демо расходился бы.
- Отвергнуто: программная экспозиция (умножение пикселей вместо выдержки). Она не добавляет света, а только растягивает шум и пересвет. Экспозиция и усиление — это то, что физически делает сенсор.
- Отвергнуто: отдельные пути обработки для превью (быстрый, на GPU) и для файла (точный, на CPU). Экран и файл могли бы разойтись, а это нарушает R10.3.

## Последствия

- Обработка нагружает CPU на каждом кадре (`unsafe` + `Parallel.For`). На слабой машине при полном кадре падает FPS, лишние кадры отбрасываются.
- Коррекция работает с 8-битными данными: сильный контраст или гамма дают постеризацию, а пересвет восстановить нельзя.
- Аппаратные контраст и гамма камеры не используются. Добавить их можно через `ICamera`, но сейчас это вне рамок.
