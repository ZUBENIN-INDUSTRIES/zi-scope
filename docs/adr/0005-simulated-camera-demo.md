# 0005. Симулятор камеры и демо-режим за общим интерфейсом ICamera

## Контекст

Камера есть только на машине с микроскопом. Разработка, тесты и показ программы идут без неё, а сигнатуры API не проверены (ADR 0001).

## Решение

Весь код, работающий с камерой, обращается к интерфейсу `ICamera`. Есть две реализации: настоящая через P/Invoke и `SimulatedCamera`. Симулятор выдаёт кадры 1920×1440 примерно 25 раз в секунду: «клетки» с дрейфом и шумом, которые реагируют на экспозицию, усиление и `Focus`. Если нет камеры или драйверов, программа показывает заглушку «Камера не подключена», раз в 3 секунды ищет камеру и предлагает демо-режим (с бейджем «ДЕМО»). Если 3 секунды не приходит ни одного кадра, программа сообщает «Связь с камерой потеряна» и переподключается сама.

## Почему

- Отвергнуто: показывать без камеры ошибку или пустое окно. R17i запрещает падение, а без камеры нельзя проверить ни один экран.
- Отвергнуто: статичная тестовая картинка вместо симулятора. На ней не проверить автоэкспозицию, фокус-ассистент, гистограмму, FPS и обрыв потока. Для этого кадры должны идти потоком и откликаться на параметры.
- Отвергнуто: мок нативной DLL на уровне P/Invoke. Это сложнее, чем подменить реализацию интерфейса, и пользователю демо-режим всё равно не даёт.

## Последствия

- UI и тесты камеры проверены только на симуляторе, а не на железе. Настоящий путь через `lucamapi.dll` остаётся непроверенным, пока программу не запустят у микроскопа.
- Симулятор нужно поддерживать вместе с `ICamera`: каждое новое свойство камеры придётся эмулировать и в нём.
- `ICamera` умеет только экспозицию и усиление. Для новых аппаратных свойств придётся расширять интерфейс и обе реализации.
