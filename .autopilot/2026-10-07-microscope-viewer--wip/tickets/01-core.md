## Что должно заработать

Фундамент, на котором стоит всё остальное, без UI. Код камеры переписан под настоящий API
`lucamapi.dll`: старый P/Invoke ссылается на несуществующий `lucam.dll`, и в нём неверны
структура формата, константа остановки и сигнатура конвертации. Есть симулятор камеры,
который рисует правдоподобный «микропрепарат» и реагирует на экспозицию, усиление и фокус.
Есть хранилище настроек и модуль программной цветокоррекции с анализом кадра (гистограмма,
резкость, средняя яркость). Всё покрыто тестами.

Старые `Camera/NativeMethods.cs`, `Camera/LuCamCamera.cs`, `Camera/CameraFrame.cs`
переписываются. `MainWindow.xaml(.cs)` в этом таске **не трогать**: его полностью заменит
таск 02. Если старое окно перестанет компилироваться из-за изменённых типов, минимально
поправь его, чтобы `dotnet build` был зелёным (например, `frame.Rgb24` → `frame.Bgr24` и
`PixelFormats.Bgr24`).

## Критерии приёмки

- [ ] NuGet в приложении: `WPF-UI` (последняя стабильная, совместимая с net8) и `CommunityToolkit.Mvvm`. Проект `tests/LumeneraViewer.Tests` (xUnit, `net8.0-windows`, x64, ссылка на приложение) добавлен в `LumeneraViewer.sln`. `dotnet build` и `dotnet test` зелёные
- [ ] `LuCamCamera : ICamera` на `lucamapi.dll` строго по сигнатурам из спецификации §4: `LUCAM_FRAME_FORMAT` — 28 байт (тест на `Marshal.SizeOf`), STOP=0 / START_STREAMING=1, `AddStreamingCallback` возвращает -1 при ошибке, `ConvertFrameToRgb24` с `LUCAM_CONVERSION{DemosaicMethod из настроек, CorrectionMatrix=0}`. Делегат колбэка хранится в поле. При PF_16 перед стартом ставится PF_8. Колбэк копирует буфер и возвращается сразу, конвертация идёт в отдельном потоке по схеме «последний кадр побеждает». Вывод — BGR24, при `SwapRedBlue` каналы R и B меняются местами. `Get/Set/GetRange` для Exposure(20)/Gain(40) через `LucamGetProperty/SetProperty/PropertyRange`. `Info` заполняется из формата и `LucamQueryVersion` (серийный номер). Все ошибки — исключения с кодом `LucamGetLastError` и русским текстом
- [ ] `CameraFactory.IsDriverAvailable()` — `NativeLibrary.TryLoad("lucamapi.dll")` без вызова P/Invoke. `CountRealCameras()` возвращает 0, если драйвера нет (без исключения)
- [ ] `SimulatedCamera`: 1920×1440, ~25 к/с в фоновом потоке. Мягкий фон с виньеткой, 40–80 «клеток» (эллипсы с ядром и мембраной, разные оттенки), медленный дрейф и шум. Яркость ∝ экспозиция·усиление (Exposure 0.1–2000 мс, по умолчанию 30; Gain 1–16, по умолчанию 1). `Focus` размывает картинку пропорционально |Focus−0.5|. Готовая сцена рендерится один раз в буфер, на каждый кадр — только сдвиг, шум и размытие, без лишних аллокаций на кадр. `Info` = ("Симулятор INFINITY 4", "DEMO", 1920, 1440, true)
- [ ] `ImageProcessor.Apply` реализует формулы спецификации: 3 LUT, насыщенность Rec.709, Ч/Б, негатив; `unsafe` + `Parallel.For` по строкам; при `IsIdentity` — быстрое копирование. Тесты: identity не меняет пиксели; гамма 2 осветляет 64 → ~128; контраст +100 растягивает от 128; насыщенность 0 даёт R=G=B; негатив; Temperature>0 → R растёт, B падает
- [ ] `FrameAnalysis`: гистограмма (сумма = число выборок), `ClippedFraction`, `ComputeSharpness` (дисперсия лапласиана по яркости в ROI; на размытом кадре меньше, чем на резком — тест на синтетике), `MeanLuma`. `ComputeGrayWorldGains` + `GainsToTemperatureTint` (тест: кадр с синим оттенком даёт Temperature > 0)
- [ ] `SettingsStore`: Load/Save/ScheduleSave(1 с)/Flush; enum строками; битый JSON переименовывается в `.bak`, возвращаются значения по умолчанию (тест); отсутствующий файл → значения по умолчанию (тест); round-trip всех полей (тест). `AppSettings` строго по составу из `interfaces.md`
