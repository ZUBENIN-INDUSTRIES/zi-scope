# Спецификация: программа для микроскопа Lumenera INFINITY 4

## Задача

Есть микроскоп с камерой Lumenera INFINITY 4 и тестовая программа, которая умеет только
показать поток и сохранить кадр. Нужна настоящая рабочая программа для микроскопии:
поставить её на любой компьютер, без поиска драйверов в интернете; смотреть живое
изображение; подстроить экспозицию и цвет; поставить плашку масштаба и сохранить снимок
в нужном формате. Выглядеть она должна современно, в духе reactbits.dev. Позже
пользователь будет дорабатывать её под узкие задачи, поэтому код должен легко расширяться.

## Решение

Пользователь получает папку с `LumeneraViewer.exe` и подпапкой `Drivers\`, где лежит
комплектный установщик драйверов. При первом запуске без драйверов программа сама
предлагает их установить, а после согласия ставит из этой папки, без интернета. Если камеры
нет, программа не падает: показывает понятное состояние и предлагает демо-режим, в котором
симулятор генерирует «микропрепарат», так что всё можно попробовать без микроскопа.

Окно в тёмной теме: анимированный фон, стеклянные панели, подсветка под курсором и
светящаяся кнопка «Снимок». В центре живое изображение с зумом и перемещением. Справа
карточки: «Камера», «Цвет», «Масштаб», «Измерения», «Сохранение». Сверху статус
подключения, FPS, разрешение и индикатор фокуса. Снизу лента последних снимков.

## Детали, без которых нельзя собрать

**Формулы коррекции** (входное значение `v` в 0…1, на канал, порядок применения):
1. Баланс белого: `v_c = v_c · k_c`, где `kR = 1 + 0.003·Temperature`, `kB = 1 − 0.003·Temperature`, `kG = 1 − 0.003·Tint` (Temperature, Tint ∈ −100…100; положительная температура — теплее, положительный оттенок — пурпурнее). Результат обрезается в 0…1.
2. Яркость: `v = v + Brightness/200` (±0.5).
3. Контраст: `c = (Contrast+100)/100` (0…2) → `c = c<1 ? c : 1 + (c−1)·2` (диапазон 0…3); `v = (v − 0.5)·c + 0.5`.
4. Гамма: `v = v^(1/Gamma)` (Gamma > 1 осветляет тени).
5. Обрезка 0…1 → ×255 → LUT. Шаги 1–5 сводятся в 3 LUT (по одному на канал).
6. Насыщенность: `L = 0.2126R+0.7152G+0.0722B`; `C = L + (C − L)·Saturation/100`, обрезка.
7. Ч/Б: все каналы = L. Негатив: `255 − v` (последним).
`GainsToTemperatureTint`: обратное к п.1 при `kG = 1` → `Temperature = (kR − kB)/0.006`, `Tint` из `kG` относительно среднего `(kR+kB)/2`; результат обрезается до ±100.

**Автоэкспозиция**: цель — средняя яркость центральных 50 % кадра = 0.45 (115 из 255), допуск ±0.03. Шаг: `exp *= clamp(target/mean, 0.25, 4)`, в пределах диапазона камеры; ждать 2 кадра после каждой установки; максимум 8 итераций, затем «Автоэкспозиция: не удалось достичь цели» (уведомление).

**Плашка масштаба**: размер шрифта 10–48 pt превью, по умолчанию 16; толщина линии 2–12 px, по умолчанию 4. При впечатывании в файл шрифт и толщина масштабируются коэффициентом `frameWidth / 1600`. Подложка — полупрозрачный чёрный (белая плашка) или белый (чёрная), α 0.55, радиус 6.

**Сетка**: шаг задаёт пользователь в карточке «Измерения». При калибровке — в мкм (по умолчанию 100 мкм), без калибровки — в % ширины (по умолчанию 10 %). Линии полупрозрачные (α 0.35), цвет как у плашки.

**Эффекты reactbits** (своими контролами, только WPF-анимации; палитра — `#0B0B12` фон, акценты `#7C3AED` фиолетовый, `#06B6D4` бирюзовый, `#F472B6` розовый):
- `AuroraBackground` — 3 размытых эллипса акцентных цветов (BlurEffect 120, α 0.35), медленно дрейфуют (12–20 с на цикл, AutoReverse, Sine easing) за всем окном.
- `SpotlightCard` — карточка со стеклянным фоном (`#14FFFFFF`, рамка `#22FFFFFF`, радиус 14); радиальный градиент акцента α 0.18, радиус 220 px, следует за курсором, исчезает за 250 мс при уходе мыши.
- `ShinyText` — заголовок «Lumenera Studio» с бегущим бликом (LinearGradient-маска, цикл 3 с).
- `CountUpText` — числа (FPS, резкость, мкм/px) анимируются к новому значению за 400 мс (CubicEase).
- `GlowButton` — кнопка «Снимок»: градиент фиолетовый→бирюзовый, внешнее свечение (DropShadow BlurRadius 24), при наведении свечение ×1.5 за 200 мс, при нажатии scale 0.96.
- `ClickSpark` — при клике 8 искр-линий разлетаются по кругу на 28 px и гаснут за 400 мс.
- Появление карточек: fade 0→1 и сдвиг Y 12→0 за 350 мс со сдвигом 60 мс между карточками.
Готовые компоненты (R12): из WPF-UI берутся FluentWindow (Mica, тёмная тема), CardExpander, ToggleSwitch, NumberBox, Snackbar, ContentDialog, SymbolIcon, ProgressRing. Эффекты выше — порт идей конкретных компонентов reactbits (Aurora, Spotlight Card, Shiny Text, Count Up, Click Spark, Star Border/Glow) на WPF.

## Решения по реализации

1. **Стек**: WPF, .NET 8 (`net8.0-windows`, x64), уже стоит в репо. Нативная программа, видео быстрое, exe один.
2. **UI-библиотека**: NuGet `WPF-UI` (lepoco/wpfui, последняя стабильная, совместимая с net8). Готовые Fluent-контролы: FluentWindow, CardExpander, NumberBox, ToggleSwitch, Snackbar, ContentDialog. Выбрана по ответу пользователя («WPF + стиль reactbits»). Эффекты reactbits (Aurora, SpotlightCard, ShinyText, CountUp, ClickSpark, GlowButton) — свои контролы в `UI/Effects`, только WPF-анимации, без сторонних шейдеров.
3. **MVVM**: NuGet `CommunityToolkit.Mvvm`. Один `MainViewModel` собирает под-модели карточек (`CameraPanelVM`, `ColorPanelVM`, `ScalePanelVM`, `MeasurePanelVM`, `CapturePanelVM`). Так проще расширять (R04).
4. **Камера (D01)**: реальный API — `lucamapi.dll` (так он называется в пакете драйверов пользователя). Сигнатуры (P/Invoke, x64, `CallingConvention.StdCall` на x64 игнорируется):

   ```c
   LONG   LucamAddStreamingCallback(HANDLE, void(__stdcall*)(void* ctx, BYTE* data, ULONG len), void* ctx); // -1 = ошибка
   BOOL   LucamRemoveStreamingCallback(HANDLE, LONG id);
   BOOL   LucamConvertFrameToRgb24(HANDLE, BYTE* dest, BYTE* src, ULONG w, ULONG h, ULONG pixelFormat, LUCAM_CONVERSION*); // вывод в порядке BGR
   BOOL   LucamGetProperty(HANDLE, ULONG prop, FLOAT* value, LONG* flags);
   BOOL   LucamSetProperty(HANDLE, ULONG prop, FLOAT value, LONG flags);
   BOOL   LucamPropertyRange(HANDLE, ULONG prop, FLOAT* min, FLOAT* max, FLOAT* def, LONG* flags);
   BOOL   LucamQueryVersion(HANDLE, LUCAM_VERSION*);
   typedef struct { ULONG xOffset, yOffset, width, height, pixelFormat;
                    USHORT subSampleX /*union binningX*/, flagsX, subSampleY /*union binningY*/, flagsY; } LUCAM_FRAME_FORMAT; // 28 байт
   typedef struct { ULONG DemosaicMethod /*HIGH_QUALITY=2*/; ULONG CorrectionMatrix /*NONE=0*/; } LUCAM_CONVERSION;
   typedef struct { ULONG firmware, fpga, api, driver, serialnumber, reserved; } LUCAM_VERSION;
   // pixelFormat: PF_8=0, PF_16=1, PF_24=2, PF_YUV422=3, PF_COUNT=4, PF_FILTER=5, PF_32=6, PF_48=7
   // property: BRIGHTNESS=0, CONTRAST=1, HUE=2, SATURATION=3, SHARPNESS=4, GAMMA=5, EXPOSURE=20 (мс), GAIN=40
   ```
   Размер кадра в потоке = `width/subSampleX × height/subSampleY`. Если формат 16-битный (PF_16), перед стартом ставится PF_8 через `LucamSetFormat`. Колбэк копирует данные и сразу возвращает управление; конвертация идёт в отдельном потоке по схеме «последний кадр побеждает». Сигнатуры восстановлены по публичному SDK, проверка на живой камере попадёт в отчёт. Перестановка R↔B и метод дебайеринга вынесены в настройки «Дополнительно», чтобы правка не требовала пересборки.
5. **Где какая коррекция**: экспозиция и усиление меняются в камере (аппаратно: это и есть «экспозиция»). Яркость, контраст, гамма, насыщенность, баланс белого, Ч/Б и негатив обрабатываются программно, одним проходом: 3 LUT на канал + насыщенность через яркость Rec.709. `unsafe` + `Parallel.For` по строкам. Обработка одна и та же для превью и для файла, поэтому на экране то же, что в файле. Почему программно: одинаково работает на всех версиях камеры и в демо-режиме.
6. **Производительность**: кадр обрабатывается в фоновом потоке; если пришёл новый кадр, а старый ещё в работе, старый выбрасывается. Гистограмма и фокус считаются по уменьшенной копии (шаг 4 px) не чаще 10 раз в секунду. Превью — один `WriteableBitmap` (Bgr24), который пересоздаётся только при смене размера.
7. **Драйверы**: «драйверы есть» означает `NativeLibrary.TryLoad("lucamapi.dll")`. Проверка идёт до первого P/Invoke, поэтому после установки DLL подхватывается без перезапуска. Установщик: первый `*.exe` в `<папка exe>\Drivers\`. Запуск через `ProcessStartInfo{Verb="runas", UseShellExecute=true}`. В сеть программа не ходит нигде.
8. **Упаковка**: csproj копирует `installer\*.exe` в `Drivers\` вывода (`CopyToOutputDirectory` и `CopyToPublishDirectory`). `publish.ps1` делает self-contained single-file exe и кладёт рядом `Drivers\` и `README.txt`. Установщик драйверов (39 МБ, проприетарный) не коммитится в git (`.gitignore: installer/*.exe`) и лежит у пользователя локально.
9. **Настройки**: `System.Text.Json`, `%AppData%\LumeneraViewer\settings.json`, сохранение с задержкой 1 с после изменения и при закрытии.
10. **Экспорт**: стандартные `BitmapEncoder` WPF (Png, Jpeg, Tiff, Bmp, Wmp). Оверлеи впечатываются через `RenderTargetBitmap` / `DrawingVisual` в полном разрешении кадра, шрифт плашки масштабируется по ширине кадра. Запись идёт во временный файл с последующим переименованием, поэтому частичных файлов нет.
11. **Тесты**: проект `tests/LumeneraViewer.Tests` (xUnit, `net8.0-windows`), проверяет только чистую логику через швы ниже.

## Открытые места

- Калибровка объективов (R15i): значений мкм/пиксель нет, пользователь калибрует сам в программе. В коде нет ни одной выдуманной цифры, профиль по умолчанию «Объектив 1 — не откалиброван».
- Сверка P/Invoke с живой камерой (D01): нужна проверка на машине с микроскопом. В «Дополнительно» есть настройки перестановки R↔B и метода дебайеринга.
