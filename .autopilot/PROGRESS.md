# ZI-scope — что осталось

Последняя сборка: `.autopilot/2026-10-13-series-projects/` — проект серии `.zisc`: состояние и метаданные всех кадров в одном файле, у снимков серии нет .json, «Открыть проект серии…» продолжает серию.

## Договорились — не пересматривать

- Старые серии (`series.zscope-series.json`) не поддерживать — «старые серии были только для тестов, в продакшене серии ещё небыли» (R10i снято)
- Метаданные кадров серии — «в серии в .zisc одним списком»; обычные снимки не трогать — «там уже есть выключатель метаданных»
- Ассоциации `.zisc` в реестре нет — «через открыть проект серии, пока без реестров»
- Работать только в папке проекта; «Документы», «Изображения», `%TEMP%`, `%AppData%` не трогать без слова пользователя; установщик драйверов не запускать; программа не ходит в сеть; новые NuGet — только с согласия

## Не доделано

- Двойной клик по `.zisc` в проводнике — отложено пользователем («пока без реестров», R09)
- На живой камере не проверены: длинная выдержка (>364 мс) с переключением частоты кадров и автоподключение после переподключения USB
- Предложено и ждёт «да»: быстрое превью с биннингом 2×2 при полном снимке; «x200» вместо «×200» в именах файлов
- Ждут решения пользователя: вернуть ли `%AppData%\ZI-scope\settings.json` из `.autopilot/2026-10-08-zi-scope-iterations/scratch/backup/zi.json`; удалять ли `%AppData%\ZI-scope\profiles\Конфигурация 1.zscope`, `%TEMP%\zs-04\`, `%TEMP%\zs-04-backup\`

## Известные баги

- Серия с пустым названием: программа подставляет дату — проект `<дата>.zisc`, а папка по умолчанию `_`; имена не совпадают (R04, слепая приёмка)
- Удаление снимка серии из ленты не правит `.zisc` — шаг станет «не снят» только при следующем открытии
- Диалог удаления в ленте для снимков серии упоминает .json, которого у них больше нет
- Подсказка «Снять без масштаба» говорит «шаг будет снят частично», а в `.zisc` у такого шага `"Status": "Done"`
