# Спецификация: проекты серий .zisc без .json у каждого кадра

## Задача
У каждого снимка серии рядом лежит свой .json — папка серии захламлена. Нужен один файл проекта серии `.zisc` в папке серии: в нём и состояние серии, и метаданные всех кадров одним списком; открыв его в программе, лаборант продолжает серию с того же шага.

## Решение

- **R01 · R02** — снимки серии больше не сопровождаются .json. Метаданные каждого кадра (время, камера, выдержка, усиление, коррекция, увеличение, мкм/px, формат, размер, впечатан ли масштаб, группа/образец/увеличение/вид) лежат в `.zisc` одним списком `Frames`, по записи на файл. Список пишется всегда — выключатель метаданных на вкладке «Сохранение» относится к обычным снимкам.
  - R02.1 Пересъёмка шага заменяет записи его кадров, «Удалить снимки» — убирает их; запись есть ровно у тех файлов, что числятся снятыми.
  - R02.2 Пути в списке — относительные (имя файла): папку серии можно перенести целиком.
- **R03 · R04 · R05** — `series.zscope-series.json` больше не создаётся. При «Начать серию» в папке серии сразу появляется `<имя серии>.zisc` (недопустимые в имени файла символы → `_`; пустое имя → `серия.zisc`); каждый снимок, пропуск, переход, пересъёмка сохраняют его атомарно, как раньше состояние.
  - R04.1 Новая серия в папке, где уже есть `.zisc` (один или несколько): вопрос «В папке уже есть проект серии «X» (если несколько — «X» и ещё N). Начать новую серию здесь? Прежний проект будет заменён (снимки останутся)». Да → все `.zisc` этой папки удаляются, пишется новый; Нет → ничего не меняется.
  - R05.1 Старый `series.zscope-series.json`, если он лежит в папке, программа не читает, не удаляет и не учитывает (старые серии сняты пользователем).
- **R06 · R07** — в конструкторе серии кнопка «Открыть проект серии…» (вместо «Открыть серию…»): стандартный диалог выбора файла с фильтром «Проект серии ZI-scope (*.zisc)», начальная папка — последняя серия или папка снимков. Открытие поднимает серию в том же состоянии: план, текущий шаг, режим пересъёмки, снятые/пропущенные шаги, карта серии.
  - R06.1 Проект, переименованный или лежащий не под «своим» именем, сохраняется в тот же файл, из которого открыт.
  - R06.2 Битый или чужой файл → уведомление «Проект серии не открыт» с причиной; текущее состояние программы не меняется. Снятый шаг, у которого пропал файл, становится неснятым (как раньше).
  - R06.3 При запуске программы «Продолжить серию «X» (n / N)?» работает по `.zisc` в последней папке серии (если `.zisc` там несколько — самый свежий по времени записи).
- **R08** — обычные снимки (вкладка «Сохранение», серийная нумерация, тайм-лапс) не меняются: их .json и выключатель метаданных — как были.
- **R09** — ассоциации `.zisc` в реестре нет; открыть — только из программы.

## Решения по реализации

- Формат `.zisc` — JSON (как остальные файлы ZI-scope), `"format": "zi-scope-series/2"`; читается только `/2`. Почему: старые серии были тестовыми (пользователь), совместимость не нужна.
- Метаданные кадра — публичный `FrameMetadata` в `Export` (тот же состав, что у .json обычного снимка — один источник правды); обычный снимок пишет .json из него же, байт в байт как раньше.
- `SaveExactAsync` перестаёт писать .json и возвращает `FrameMetadata` записанного файла; `SeriesRunner` получает его от сохраняющего делегата, после переименования на место ставит итоговое имя и передаёт в `SeriesSession.MarkDone`.
- `AppSettings.LastSeriesFolder` остаётся (без миграции настроек); проект в папке ищет `SeriesStore.FindProject`.
- Логика runner'а про парные .json (`JsonOf`, `DeleteWithJson`, удаление .json в `Delete`) убирается.
