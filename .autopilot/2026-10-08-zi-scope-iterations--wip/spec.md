# Спецификация: ZI-scope — серии съёмки, новый дизайн, глубокий цвет, профили

## Задача

Пользователь снимает на микроскопе большие серии: например, 16 режимов сплавления по 4 образца,
каждый образец под ×100 и ×200, каждый кадр в двух видах (без масштаба и с масштабом). Сейчас
каждый файл приходится называть и переключать настройки вручную. Нужна программа, которая
ведёт по серии шаг за шагом. Пользователь навёлся, нажал кнопку, и в папку легли оба файла
с правильными именами. Калибровка и цвет переключаются сами под нужное увеличение.
Нужно уметь быстро переснять, удалить или перенумеровать кадр. Отдельно — переименование в
ZI-scope, спокойный современный дизайн вместо «неонового» и тонкие настройки цвета как в
Lightroom с профилями.

## Решение

Программа называется ZI-scope. Интерфейс в духе Figma, Linear и VS Code: графитово-серый
(не чёрный), плоские панели с тонкими границами, синий акцент только на активных элементах,
без свечений и градиентов. В шапке — переключатель текущего увеличения (×100 … ×2000): для
каждого увеличения программа помнит свою калибровку масштаба и свои настройки цвета.
Новая вкладка «Серия»: конструктор (группы, образцы, увеличения, виды кадра) и прогон.
Прогон — это крупная кнопка «Снять шаг», карта шагов с отметками и действия «переснять»,
«удалить», «перейти к шагу», «назначить номер». Серия переживает перезапуск программы.
Окно «Глубокие настройки цвета»: каналы RGB и уровни, тон (светлые, тени, белые, чёрные),
чёткость, красочность, HSL по 8 цветам, резкость. Профили цвета и профили всей
конфигурации можно сохранять, загружать, экспортировать в файл и импортировать.

## Решения по реализации

1. **Стек не меняется**: WPF, .NET 8, WPF-UI 4.3.0, CommunityToolkit.Mvvm. Тема — тёмная WPF-UI с акцентом `#3B82F6` (`ApplicationAccentColorManager.Apply`), плюс свои токены палитры в `UI/Effects/Palette` и `Effects.xaml`. Эффекты reactbits (`AuroraBackground`, `ShinyText`, `ClickSpark`, glow у `GlowButton`, подсветка `SpotlightCard`) из разметки убираются. Файлы удаляются, если их больше никто не использует. `CountUpText` остаётся.
2. **Переименование**: `AssemblyName` = `ZI-scope`, `Product`/`Title` = `ZI-scope`. Пространства имён `LumeneraViewer.*` и имена проектов/папок в репозитории **не меняются**: пользователь их не видит, а переименование сломало бы историю. Папка настроек и папка снимков по умолчанию — `ZI-scope`. Миграция настроек — история 2.
3. **Увеличение как ключ профиля** (R12, R13, R25i): `AppSettings.Magnifications: List<MagnificationProfile>`, где `MagnificationProfile { int Magnification; double? MicronsPerPixel; double? ScaleBarMicrons /* null — Авто */; ImageAdjustments Adjustments; float? ExposureMs; float? Gain; }`. `AppSettings.CurrentMagnification: int`. По умолчанию профили ×100 и ×200, без калибровки и с нейтральным цветом. Текущие `Adjustments/ExposureMs/Gain` на верхнем уровне `AppSettings` остаются «живыми» значениями текущего увеличения. При переключении текущие сохраняются в профиль старого увеличения, а из нового загружаются в живые; изменение живых значений записывается в профиль текущего увеличения. Мкм/px для плашки берётся из профиля текущего увеличения. Список объективов (`Objectives`) больше не показывается: он только источник для ручного переноса (история 10).
4. **Глубокий цвет** (R14, R15): `ImageAdjustments` получает поле `DeepColor Deep` (запись со значениями по умолчанию = нейтраль). `IsIdentity` учитывает и его. Конвейер `ImageProcessor.Apply`: (1) баланс белого и усиление RGB; (2) экспонирование ×2^EV; (3) тон: белые/чёрные, светлые/тени — кривая по яркости с плавными масками; (4) уровни по каналам и общий, затем тональная кривая (общая и по каналам — тоже через LUT); (5) основные яркость/контраст/гамма; (6) HSL по 8 секторам оттенка с плавными весами; красочность и насыщенность; (7) локальные операции: чёткость (локальный контраст через размытие яркости большим радиусом), удаление дымки (упрощённо: локальный контраст + подъём чёрной точки), резкость (unsharp mask малого радиуса); (8) Ч/Б и негатив. Поточечная часть (1–6) идёт через LUT там, где это возможно. Размытие — сепарабельное box/«почти гауссово», с параллелизмом по строкам и переиспользуемыми буферами. Локальные операции считаются, только если они ненулевые. Цель по скорости — история 25.
5. **Профили** (R16, R17): `AppSettings.ColorProfiles: List<ColorProfile>`, где `ColorProfile { string Name; ImageAdjustments Adjustments; bool IncludesExposure; float? ExposureMs; float? Gain; }`. Старые `Presets` при загрузке переносятся в `ColorProfiles` один раз, а `Presets` очищается. Профили конфигурации хранятся файлами в `%AppData%\ZI-scope\profiles\<имя>.zscope` (полный `AppSettings` в JSON, без самого списка профилей конфигурации), экспорт и импорт — тем же форматом. `.zcolor` — JSON одного `ColorProfile` с полем `"format": "zi-scope-color/1"`, `.zscope` — `"format": "zi-scope-config/1"`.
6. **Серия** (R05–R11, R19–R21, R23i, R24i): модуль `Series/` без UI. `SeriesPlan` — конструктор, `SeriesStep` — шаг, `SeriesState` — статусы, `SeriesNaming` — имена, `SeriesStore` — JSON в папке серии. Сохранение шага использует существующий `FrameExporter`, по одному вызову на вид кадра. Оформление вида задаёт, какие оверлеи впечатываются: `Clean` — без оверлеев, `ScaleBar` — только плашка масштаба (без сетки, перекрестия и измерений), `ScaleBarAndMeasurements` — плашка и измерения. Формат файла серии и метаданные `.json` берутся из настроек экспорта (метаданные дополняются полями серии: группа, образец, увеличение, вид).
7. **Сохранение файлов серии**: имя по шаблону без суффиксов `_2` и `_clean`. Существующий файл перезаписывается только при пересъёмке или после подтверждения. Каждый вид — отдельный файл, отдельной копии `_clean` нет.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R11 — виды кадра 3, 4, 5 «с измерениями» | пользователь: «пока оставь на будующее … сейчас можешь сильно не развивать»; список видов расширяемый, одно оформление «с плашкой и измерениями» доступно уже сейчас |
| R15 — раздел «Калибровка камеры» Lightroom (сдвиги основных цветов, DCP-профили) | узкие настройки закрыты тоном, кривой, присутствием, HSL и деталями; калибровка камеры в Lightroom — редкая и специализированная, её можно добавить следующим заходом |
| Автоопределение увеличения по микроскопу | у INFINITY 4 нет сведений об объективе; увеличение меняет пользователь руками, программа только подсказывает |
